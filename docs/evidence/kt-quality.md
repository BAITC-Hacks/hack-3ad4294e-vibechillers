# Проверка качества Function Lineage Auditor

## Разметка и проверка источников

На 23.09.2026 вручную сопоставлены 20 реальных пар редакций v8→v9 (§§2.4, 3, 4, 5). Ещё пять случаев получены из отдельных копий v9: удаление, дублирование, перенос, перенумерация и изменение пробела. Эталонные статусы записаны до получения отчёта системы.

Команда из корня репозитория:

```sh
uv run --no-sync python eval/kt/score.py --validate-labels
```

Результат: `Validated 25 labels: 20 real, 5 synthetic; all fixture hashes, clause refs and quotes resolve`. Проверены SHA-256 каждого файла, наличие каждого `clause_id` и точное вхождение каждой цитаты в соответствующий пункт.

## Первое измерение

23.09.2026, после коммита ядра `d61263c`: вызван `app.audit.run_deterministic_audit` — тот же детерминированный конвейер, который вызывает `POST /audits`. Входы: v8.txt→v9.txt и пять отдельных сравнений v9.txt→`mutations/*.txt`. Каждый полученный объект `Report` передан `eval/kt/score.py`. Это измерение доменного конвейера; HTTP/SSE и сохранение отчёта по `GET /audits/{run_id}` в данной среде пока не проверены.

Реальный отчёт содержит 457 находок. Покрытие функций: 420/420 до, 413/413 после; 33 находки `unresolved` по всему документу. Из них в выбранных 20 эталонах одно воздержание.

Итого точных совпадений: 19/20 реальных и 5/5 синтетических. Реальный случай `real-019` (§5.3.6→§5.3.7) остался `unresolved`. На фикстуре дублирования система верно выдала `duplicate`, но также отдельное `unchanged` для исходной функции; оно создаёт одно лишнее срабатывание в precision статуса `unchanged`.

Оценщик сравнивает точные множества ссылок и статус. Precision считает только находки, пересекающиеся с размеченными ссылками; вне этих ссылок эталон не утверждает правильность или ошибку. `unresolved` считается воздержанием. Проверить новый отчёт можно командой `python eval/kt/score.py path/to/report.json`.
